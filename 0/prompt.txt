# Harden Beta Release Readiness

## Summary

Implement findings 2–9 in one reviewable PR; do not implement finding 1 because the canary API and workflow writers are both fixed at 4 MiB, so the described oversized-artifact mismatch cannot occur. Preserve the existing readiness-report schema version and persisted ledger JSON compatibility.

## Implementation Changes

- Make readiness execution bounded:
  - Thread `context.Context` through the command seam and use `exec.CommandContext`.
  - Apply a 60-second timeout to each Git/uv/Docker command and a five-minute overall CLI timeout.
  - Preserve stdout-only comparisons and caller cancellation.

- Add redacted diagnostics:
  - Add `failed_check,omitempty` to `release.Report`.
  - Populate it through typed internal failures rather than matching or printing error strings.
  - Use stable values for configuration, source checkout, toolchains, migrations, files, images, workflow/runtime, reasoning, verification, review, approval, publication, GitHub draft, and human decision failures.
  - Document the additive report field and retain exit codes 0/1/2.

- Tighten verification-ledger binding:
  - Select the completed row by the artifact’s `VerificationID`, decode its full `result_json`, and require matching verification ID, candidate commit, report artifact reference, and passed result.
  - Add explicit JSON tags using the existing PascalCase keys on `verification.Result`, preserving all previously stored ledger rows and replay behavior.
  - Remove the global candidate-commit count predicate.

- Harden evidence handling:
  - Have reasoning verification return the validated review invocation, eliminating the unguarded `invocations[1]`.
  - Replace duplicate directory hashing with one shared beta helper that rejects symlinks/non-regular files, allows at most 64 files, limits each file to 1 MiB, and hashes by streaming. Use it for both deployment-record generation and readiness verification.
  - Add `set -euo pipefail` to the multi-command `beta-canary-e2e` recipe so setup stops at the first failure.
  - Remove unused `DeploymentRecord.Digest` and narrow `verifySupplyChain` to return only the configuration consumed by its caller.
