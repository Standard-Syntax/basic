# Vertical Slice 6: Beta Service Packaging

## Summary

Package `api-service` and `workflow-service` as pinned, non-root images and run them with PostgreSQL through a hardened beta Compose profile. Slice 6 will remain one canonical PR, `beta/service-packaging`, with focused Conventional Commits.

The packaged workflow service will use Docker’s official Go SDK with API-version negotiation instead of requiring the Docker CLI. This preserves the existing worker-container isolation while keeping Docker out of the final image. [Docker Engine SDK guidance](https://docs.docker.com/reference/api/engine/sdk/)

## Implementation Changes

- Replace execution and verification Docker CLI calls with a small consumer-owned Engine interface backed by `github.com/moby/moby/client`. Preserve image-digest inspection, non-root UID/GID, no network, read-only worker roots, bounded output, exact mounts, and named-container cleanup on cancellation.
- Add file-backed MiniMax credentials that validate a clean absolute, owner-only `0600` file and reread it for every invocation. Existing host/live gates retain `ANTHROPIC_API_KEY`; packaged configuration permits exactly the file source, with no ambiguous fallback.
- Make workflow shutdown stop new claims immediately, continue heartbeat renewal while the current claim drains, and cancel after a configured 60-second deadline. Recovery remains fence-safe if draining expires.
- Add dependency-aware `/healthz` and `/readyz` endpoints to both services. Readiness checks PostgreSQL, applied migration digests, CAS accessibility, bound worker image availability, configuration, and credential presence without invoking MiniMax or mutating Git/workflow state.
- Extend authenticated `GET /v1/runs/{run_id}` with stage status and terminal failure artifact references. Logs retain structured run/task/stage/job/fence fields and failure digests, never proposal bodies, credential material, or provider responses.
- Add multi-stage `Dockerfile.api-service` and `Dockerfile.workflow-service`. Final images use fixed UID/GID `65532:65532` and contain only the service binary, CA certificates, the pinned Git runtime and its required libraries. Base images and installed Git version are pinned; source revision and component metadata use OCI labels.
- Add `beta_deployment.v1`, a strict secret-free deployment envelope containing common beta policy, service settings, immutable service/worker image IDs, mount paths, and credential-file paths. Unknown fields and mutable image tags fail closed.
- Add a beta Compose profile with:
  - PostgreSQL persistent storage and health checks;
  - host-loopback exposure only for the API;
  - internal workflow health traffic;
  - read-only root filesystems, dropped capabilities, `no-new-privileges`, bounded tmpfs, and explicit shutdown grace periods;
  - repository mounts at identical host/container absolute paths, read-only for API and writable only where workflow Git operations require it;
  - dedicated CAS, worktree, verification, manifest, prompt, configuration, and credential mounts;
  - the Docker socket mounted only into workflow-service, with an explicitly configured supplemental socket group.
- Add `beta_deployment_record.v1` generation containing the source commit, migration digest, manifest and prompt digests, worker and service image IDs, Git/Go/toolchain versions, and configuration digest. It contains no secrets or live-run evidence; Slice 7 will consume it.
- Add `make beta-images` and `make beta-deploy-smoke BETA_CONFIG=/absolute/path/to/beta.json`. Update `beta-live-e2e` so supplying `BETA_CONFIG` exercises the same packaged images.
- Document provisioning, PostgreSQL/CAS backup and restore, credential rotation, failed-claim recovery, canary cleanup, deployment-record retention, and rollback to the prior exact image set. Record the packaging/security decision in the decision log.
