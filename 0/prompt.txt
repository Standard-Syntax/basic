## Implementation Changes

- Add deterministic prompt authoring from shared fragments for authoritative inputs, evidence discipline, output-only behavior, kernel-owned identity, and proposal-only authority. Stage-specific fragments define responsibility, reasoning procedure, supported missing-evidence channel, and schema name.
- Render static UTF-8 prompt files with LF endings and one terminal newline before compiling manifests. Fail generation on unknown placeholders, missing fragments, duplicate sections, or nondeterministic output; include the four rendered prompts in `make generate-check`.
- Rewrite each stage around the current v1 contract:
  - Specification produces bounded requirements, observable acceptance criteria, constraints, non-goals, assumptions, risks, and blocking questions without implementation design.
  - Planning creates the smallest complete acyclic graph, traces every task and required check to approved criteria, uses dependencies only for technical necessity, and records unresolved scope through `unresolved_scope_questions`.
  - Implementation emits exact complete-file candidate content, expected original digests, criterion coverage, and only available declared checks. It never claims application or verification. Missing scope or evidence is expressed through `unresolved_questions` and `scope_change_request`; no out-of-scope change may be proposed.
  - Review applies the evidence hierarchy, uses only supplied evidence IDs, derives blocking status from review policy and severity, reports unexpected paths separately, and represents unsupported evaluation as `rework_required` plus assumptions/residual risk rather than fabricated findings.
- State that models populate only fields exposed by the provider-supplied closed schema. Trusted Go injects request, task, specification, manifest, and artifact identities before kernel validation.
- Clarify that manifest request capabilities are kernel-mediated and unavailable during current tool-free Anthropic calls. Requests must never be embedded as prose around the final JSON.
- Update all four agent definitions to `1.1.0`, regenerate manifest JSON/digest fixtures, and document that prompt-byte changes require a new immutable agent version.
- Record the current v1 limitation: there is no universal blocker/evidence-request structure, and an incomplete implementation proposal may be rejected without advancing workflow state. Universal blocker handling and live specification/planning adapters remain deferred.
