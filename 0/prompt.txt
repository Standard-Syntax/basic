## Implementation Changes

- Reuse the existing strict `BETA_CONFIG` preflight shape for the canary gate, extracting shared decoding where necessary. Require:

  - dedicated repository `Standard-Syntax/basic-beta-canary`;
  - base branch `main`;
  - canonical fixture files `add.go`, `add_test.go`, and `Makefile`;
  - only `add.go` writable;
  - repository-owned `make-check-v1`;
  - pinned execution and verification image digests;
  - `ANTHROPIC_API_KEY`;
  - an owner-only `0600` GitHub REST token file;
  - separately provisioned least-privilege Git push authentication.

- Add `make beta-canary-e2e BETA_CONFIG=/absolute/path/to/canary.json`. It must:

  - run production preflight first;
  - build and start the real API/workflow binaries and isolated workers;
  - create unique run, task, approval, publication, and `harness/canary/<run-id>` identities;
  - invoke MiniMax-M2.7 exactly once for implementation and once for review;
  - change only `add.go` and pass the repository-owned check;
  - publish through `GitCommandPublisher` and `GitHubRESTClient` to `https://api.github.com`;
  - refetch the real PR and verify open/draft state, exact base branch/base commit, head branch/candidate commit, verified diff, publication artifact, and URL;
  - restart the API and replay approval, proving unchanged response, exactly one named remote branch and PR, and no additional provider invocation;
  - emit secret-free JSON containing the run ID, publication ID, candidate commit, artifact reference, PR URL, and exact cleanup command.

- Extend concrete publication clients with inspection and cleanup operations without adding close/delete authority to the runtime `PullRequestClient` or `GitPublisher` interfaces:

  - inspect a PR by exact owner/repository/number;
  - close only an open draft whose marker, base, head, and candidate match;
  - delete only the exact named branch when its remote head still equals the recorded candidate;
  - treat already-closed/already-deleted matching state as idempotent success and fail closed on every mismatch.

- Add `make beta-canary-cleanup BETA_CONFIG=... CANARY_PUBLICATION_ID=...`. A separate command loads the completed immutable publication record and artifact, validates them against the configured canary policy, closes that one draft, and deletes that one exact branch. Cleanup never uses prefixes or broad patterns and is not part of successful canary acceptance.

- Document the canary provisioning, credential scopes, exact run and cleanup commands, evidence interpretation, recovery from partial cleanup, and the continuing prohibition on merge/deploy. Record the dedicated-canary and separate-cleanup authority decision in the decision log.
