## Implementation Changes

- Replace the Make targets:

  - `make runtime-e2e`: credential-free PostgreSQL/CAS/reconciler recovery test using pre-existing immutable artifacts; it must make no reasoning-provider call.
  - `make beta-live-e2e`: require `ANTHROPIC_API_KEY`, build both service binaries and worker images, start disposable PostgreSQL, and run the complete live process test.
  - Remove `minimax-live-e2e` and `MINIMAX_LIVE_E2E`.

- Refactor the process fixture into an unconditional beta-live scenario:

  - Remove `fakeProposals`, proposal-path configuration, fake evidence branches, and the `live` parameter.
  - Configure only `minimax_anthropic`, `https://api.minimax.io/anthropic`, `MiniMax-M2.7`, and `ANTHROPIC_API_KEY`.
  - Retain the disposable Git repository, real execution and verification containers, and loopback GitHub server.
  - Keep task-specific implementation/review prompts that demand one in-scope `add.go` correction and evidence-based review.

- Strengthen successful-run evidence:

  - Require exactly one accepted implementation row and one accepted review row, distinct request identities, one provider request each, non-empty request IDs and token usage, and integrity-valid proposal/raw-response artifacts.
  - Require a non-base candidate changing only `add.go`, passing independent `make check`, with exactly one verification, review, human approval, draft publication, remote harness branch, and open draft PR bound to the expected base and candidate.
  - Restart the workflow service before approval and restart the API before replaying the same approval request with the same idempotency key. The replay must return the original response without new provider calls, approval rows, pushes, or PR creation.
  - Scan configuration, prompts, process logs, CAS contents, PostgreSQL export, and reachable fixture Git content for the provider secret.

- Add deterministic terminal-path coverage through consumer-owned test ports:

  - Provider timeout/transport failure exhausts bounded retries, records one failed stage artifact, and enqueues no successor.
  - Malformed provider JSON and an empty-change proposal become `SCHEMA_INVALID` proposal rejection with no execution.
  - Failed verification moves the task to rework and never invokes review.
  - `rework_required` review moves the task to rework and never exposes approval or publication.
  - Production-adapter loopback tests continue to own provider protocol/error translation; no provider-output substitute is added to shipped composition.

- Update active documentation and add a decision-log entry distinguishing deterministic infrastructure evidence, provider smoke, and the credentialed beta gate. Remove the historical mixed-fixture warnings only after the new targets work; do not rewrite historical completion facts.
